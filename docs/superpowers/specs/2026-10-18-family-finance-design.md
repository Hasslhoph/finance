# Семейные финансы — описание продукта

Дата: 18 октября 2026
Статус: на согласовании

## Зачем

Саша и Таня хотят видеть цельную картину семейных денег: сколько есть всего, сколько
доступно, сколько заработали за период, сколько отложили и на что уходит. Сейчас это
разрозненные приложения банков и ощущения. Нужен один экран, которому можно верить, и
ввод трат, который не бросают через две недели.

Главный вопрос, на который отвечает сервис: **«как у нас дела и сколько мы отложили за
этот период»**. Всё остальное на дашборде существует, чтобы на него ответить.

## Что это

Личный (не коммерческий) веб-сервис для двоих. Одна база, один вход по логину и паролю.
Атрибуция «Саша / Таня» — это поле записи, а не отдельный аккаунт: заполняет только Саша.

Размещается на существующем VPS с AmneziaWG, открыт по обычному HTTPS-адресу.

## Цели

1. Ввод трат вечером пачкой — быстро, с телефона и с ноутбука.
2. Дашборд: всего денег, доступно, заработок по каждому, проценты отдельно, отложено,
   расходы по категориям, подсказки о перерасходе.
3. Любой период: текущий месяц, 3, 6, 12 месяцев — и произвольный диапазон.
4. Проценты по вкладу вносятся как обычное поступление и сами увеличивают тело вклада.
5. Сервис говорит на человеческом языке, где вы потратили заметно больше обычного.

## Не-цели первой версии

- Телеграм-бот и разбор трат нейросетью (строим API так, чтобы влезло позже).
- Ассистент, который сам даёт финансовые советы.
- Импорт выписок из банков, OCR чеков.
- Мультивалютность (только рубли).
- Бюджеты и лимиты по категориям.
- Несколько пользователей с разными правами.
- Долги, кредиты, ипотека, рассрочки. Учёт только денег: проценты по кредиту, если
  появятся, вносятся обычным расходом.
- Внос истории задним числом: учёт начинается с даты старта, остатки вводятся на неё.

## Анти-цели

- Сервис, в который надо заходить «когда будет время». Если ввод не занимает секунды,
  проект провалился, даже если дашборд красивый.
- Красивые цифры, которым нельзя верить: любое расхождение с реальными остатками должно
  быть видно, а не сглажено.
- Тяжёлый стек, из-за которого пострадает VPN на том же сервере.

## Решения, принятые пользователем

- Старт с нуля: остатки вводятся на дату начала учёта, прошлые месяцы не заносятся.
- Кредитов, ипотек и рассрочек нет — модель долгов не нужна.
- Публичный HTTPS-адрес, без VPN-онли. Один логин и пароль, задаются при настройке.
- Бесплатный домен DuckDNS (свой домен не покупаем).
- Ручной ввод, вечером, по выписке из карты, пачкой за день.
- «Отложено» = все поступления минус все траты за выбранный период. Переводы между
  своими счетами не траты и не доходы.
- Проценты по вкладам — отдельная категория дохода, вносится фактом по мере начисления
  (раз в месяц у Саши, раз в квартал у Тани).
- Тёмное оформление, цветные графики, современный вид уровня американских SaaS.
- Стек: React + современный HTML/CSS/JS.

## Решения, принятые исполнителем (мои)

- **Стек:** React 19 + Vite + TypeScript, Tailwind CSS, Recharts для графиков.
  Сервер: Node 22 + Fastify + SQLite (better-sqlite3), отдача статики и API через Caddy
  с автоматическим HTTPS.
- **Деньги:** целые копейки в БД, форматирование только на клиенте. Никаких float.
- **Часовой пояс:** Europe/Moscow для границ периода, сервер живёт в Амстердаме.
- **Аутентификация:** один пользователь, логин и scrypt-хеш пароля (встроенный
  `node:crypto`, без нативных зависимостей) в env-файле, сессия в httpOnly Secure cookie,
  ограничение попыток входа.
- **Переводы:** запись вида «перевод» со счётом-источником и счётом-назначением; в
  отчётах не участвует ни в доходах, ни в расходах.
- **Сверка остатков:** ручной ввод фактического остатка по счёту. Разница становится
  реальной записью в журнале — расходом или доходом в служебной категории «Нераспознанное»,
  чтобы остаток сошёлся, а «отложено» не показывало денег, которых нет. Если позже
  добавить операцию задним числом и баланс снова разойдётся, сервис предложит новую сверку;
  старые сверки не пересчитываются.
- **Подсказки о перерасходе:** сравнение с тремя предыдущими окнами той же длины; если
  истории меньше двух окон, подсказок нет. Учёт стартует с нуля, поэтому в первый месяц
  подсказок не будет — это ожидаемо и должно быть написано в интерфейсе. Порог 1.5× и минимальная абсолютная сумма
  (2 000 ₽) — константы в настройках. Правило объясняется в интерфейсе словами.
- **Категория процентов:** у категорий есть системный признак `slug`; «Проценты по вкладу»
  помечена как `interest-income`, её нельзя удалить и нельзя переименовать в другую роль —
  дашборд опирается на признак, а не на название.
- **Бэкапы:** Mac сам забирает дампы с сервера (pull по SSH), сервер не хранит чужих
  ключей; на сервере держим 7 последних копий.
- **Экраны:** дашборд, лента операций, ввод (быстрый), счета, категории, настройки.
- **Мобильная версия:** не отдельное приложение, а адаптив; ввод на телефоне — главный
  сценарий, проверяется первым.
- **Эксплуатация:** systemd-юнит с `MemoryMax=256M` и `CPUQuota=50%`, swap 2 ГБ, ночной
  бэкап базы с ротацией на сервере и выгрузкой на Mac.

## Модель данных

- `accounts` — счёт: название, вид (карта / наличные / вклад), владелец (Саша / Таня /
  общий), начальный остаток и дата, на которую он верен, архив.
- `categories` — категория: название, группа, вид (расход / доход), цвет, иконка,
  порядок, архив.
- `transactions` — операция: вид (расход / доход / перевод), дата, сумма в копейках,
  счёт, категория (для расхода и дохода), счёт-назначение (для перевода), кто
  (Саша / Таня), комментарий, создано/изменено.
- `balance_checks` — сверка: счёт, дата, фактический остаток, вычисленный остаток,
  разница.
- `sessions` — сессии входа.

Остаток счёта = начальный остаток + поступления − расходы + переводы на счёт − переводы
со счёта. Вклады — те же счета, поэтому начисленные проценты (доход на счёт вклада)
увеличивают и «на вкладе», и «всего денег».

## Правила дашборда

- **Всего денег** = сумма остатков всех активных счетов.
- **Доступно** = всего денег минус остатки на счетах вида «вклад».
- **Заработано за период** — по каждому человеку отдельно: сумма доходов, где категория
  не «проценты по вкладу».
- **Проценты по вкладам** — отдельная строка дохода за период.
- **Отложено** = все поступления − все траты за период. Переводы исключены.
- **Расходы по категориям** — круговая диаграмма, группы сворачиваются.
- **Перерасход** — категории, где траты периода выше медианы прошлых периодов в 1.5 раза
  и больше, с человеческой подписью и суммой превышения.

## Состояние сервера (проверено)

VPS `82.25.39.32`, Ubuntu 24.04, 1 vCPU, 891 МБ RAM, свопа нет, 31 ГБ свободно, часовой
пояс Europe/Amsterdam. AmneziaWG занимает UDP 443 и UDP 51820, веб-панели нет, Docker
установлен, но контейнеров нет. **TCP 80 и 443 свободны**, веб-сервера нет. UFW: входящие
по умолчанию DROP, открыты только 22/tcp и два UDP-порта. Fail2ban сторожит только SSH.

Отсюда обязательное: swap 2 ГБ, `MemoryMax` и `CPUQuota` на приложение, открыть 80/tcp и
443/tcp, поставить Caddy как единственный веб-сервер.

## Сквозные требования

- Валюта рублей, формат `12 345 ₽`, разряды тонким пробелом.
- Даты и границы периодов — по Москве.
- Тёмная тема как основная, светлая не обязательна.
- Адаптив: 360 px телефон, 768 планшет, 1280+ ноутбук.
- Доступность: контраст не ниже AA, фокус с клавиатуры, подписи к полям.
- Все изменения — через API, даже если первый клиент — сам веб-интерфейс.

Порядок экранов, точный вид графиков, названия полей API, схему миграций, формат
бэкапов — на усмотрение исполнителя в рамках этого документа.
